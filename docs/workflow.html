⚡ Power BI Agentic — Best Practice Analyzer Workflow

How any Power BI developer runs the Best Practice Rules against a .pbix and gets a pass/fail HTML dashboard. Four lanes: Setup (once) → Activate → Run → Review.

Lane 1 · Setup (one time)

1

Run the installer

Double-click setup\setup.bat. It checks Node.js & VS Code, installs the powerbi-modeling MCP server only if missing, and writes .mcp.json (read-only).

→
2

Prereqs verified

Node.js 22+, VS Code, and Power BI Desktop. The script tells you if anything is missing — no silent surprises.

→
3

Server registered

Auto-detect: VS Code extension if present, else zero-install npx fallback that always pulls the latest.

Lane 2 · Activate

4

Open the model

Open your .pbix in Power BI Desktop and keep the window open — the live engine serves the model.

→
5

Reload VS Code

Ctrl+Shift+P → Developer: Reload Window so the MCP server becomes live in the session.

→
6

Connect

Tell the agent: Connect to 'AI Summaries' in Power BI Desktop (name = title bar).

Lane 3 · Run the BPA agent

7

Ask the agent

@bpa-agent run BPA on "AI Summaries.pbix" using the PowerBI rule set. Inputs: file name + rule set.

→
8

Read model via MCP

Agent lists tables, columns, measures, relationships & properties through the MCP server. Never reads the binary file directly.

→
9

Evaluate rules

For each rule's Scope, evaluate its Expression. A matching object = a violation → rule fails.

Lane 4 · Review the report

10

Timestamped report

Writes output\BPA\<model>\<model>_<ruleset>_<timestamp>.html. Each pbix keeps its own history — nothing overwritten.

→
11

Dashboard opens

KPI cards, pass/fail by category, failures by severity, and a filterable table with offending objects + remediation.

→
12

Track changes

Re-run anytime. Compare timestamped files in the model's folder to see issues fixed / introduced over time.

Input / Output contract

INPUT
The .pbix file name (open in Power BI Desktop)  +  the rule set (PowerBI · 26 rulesstandard · 29 rules).
OUTPUT
A self-contained HTML dashboard per run, naming every rule Pass / Fail / N·A / Not-Evaluated with severity, offending objects and fix guidance.
output/ BPA/ AI Summaries/ AI Summaries_PowerBI_20261022-143015.html AI Summaries_PowerBI_20261101-091244.html <- history Sales Model/ Sales Model_standard_20261103-100502.html

Result statuses

Pass — no objects match the rule Fail — ≥1 violating object (listed) Pass (N/A) — no objects in scope Not Evaluated — data unavailable

Rule categories

DAX ExpressionsFormatting MetadataModel Layout Naming ConventionsPerformance

Severity 1 (cosmetic) → 5 (critical). Higher-severity failures sort to the top of the report.
